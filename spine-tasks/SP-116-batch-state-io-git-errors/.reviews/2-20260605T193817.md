## Plan Review: Step 2 — Git error surfacing

### Verdict: APPROVE

### Summary

Step 2 correctly targets SP-106 Finding #6: stop swallowing git inspection failures in `inspectGitState` and surface an actionable `git_unavailable` diagnosis instead of letting reconcile fall through to `limbo_stale` or `needs_integrate`. The right shape is to add `inspectionError` on the `inspectGitState` result, capture the first git failure across the helper chain (not only the `branch --merged` and `countCommitsAhead` catches called out in the audit), short-circuit `deriveDiagnosis` after `orphanRunning` when `git.inspectionError` is set, and wire `git_unavailable` messaging in `diagnosis.mjs` with `spine doctor` as the suggested command. A focused `tests/batch/reconcile-git-error.test.mjs` using an env-guarded git throw (same pattern as `SPINE_TEST_GIT_PORCELAIN_THROW` in `lane-commit.mjs`) on a limbo-stale fixture satisfies the completion criterion without waiting for Step 3's full-suite gate.

### Issues Found

None blocking.

### Missing Items

- **Unified error capture scope** — PROMPT says "replace empty catch"; plan must cover every `catch` in the `inspectGitState` call tree (`isInsideGitRepo`, `gitRefExists`, `gitIsAncestor`, `listOrchBranches`, `countCommitsAhead`, `branch --merged`), not only the two audit-highlighted blocks. Otherwise `rev-parse` failure still returns `inGitRepo: false` and limbo batches can misdiagnose as `limbo_stale`.
- **`deriveDiagnosis` ordering** — `git_unavailable` must run after `orphanRunning` (orphan is more specific) and before limbo/integrate branches that depend on git merge signals.
- **`diagnosis.mjs` taxonomy** — add `git_unavailable` to `DIAGNOSIS_TAXONOMY` plus `buildHeadline` / `buildSuggestedCommand` / `buildAlternatives`; mirror `launchFailureKind → spine doctor` wording from SP-105.
- **Test artifact in Step 2** — file scope lists `tests/batch/reconcile-git-error.test.mjs`; include at least one test proving git failure yields `git_unavailable` + `spine doctor`, not `limbo_stale`/`needs_integrate`. Defer full suite + coverage to Step 3.
- **Step 2 verification gate** — before commit: `npm run typecheck`, new reconcile-git-error test, and existing `tests/batch/reconcile.test.mjs`.
- **STATUS plan blurb** — add Step 2 plan subsection (error field, diagnosis branch, test hook) per Review Level 2 hygiene before implementation commit.
- **Scope guard** — no `batch-state.json` schema changes; no `integrate.mjs` edits in Step 2 (API extension on `inspectGitState` is backward compatible).

### Suggestions

- **First-error-wins helper** — small internal `recordGitInspectionError(result, err, operation)` keeps catches readable and preserves the first failure message for `signals.git.inspectionError` / verbose `--diagnose`.
- **Test hook naming** — prefer `SPINE_TEST_GIT_INSPECTION_THROW` with operation-specific values (e.g. `branch_merged`, `rev_parse`) over monkey-patching `child_process` globally.
- **Headline copy** — e.g. "Batch git inspection failed — repair repo/worktree health before retrying integrate/dismiss" so operators know the wrong command was avoided.
- **Do not journal-write in Step 2** — audit allows journal hints as an alternative; prefer `git_unavailable` diagnosis path only unless a later task needs persistent hints.
