## Plan Review: Rules-manifest merge auto-resolve

### Verdict: APPROVE

### Summary

The Step 1 plan in `STATUS.md` is sound and matches the PROMPT mission: when `mergeLaneToOrch` hits a failed `git merge`, detect whether the only unmerged path is `.spine/rules-manifest.json`, compare a semantic fingerprint that ignores `generatedAt`, and if `rules[]` / `excluded[]` / `rulesRoot` (and top-level `warnings[]`) are identical, write the resolved manifest with `max(generatedAt)`, `git add`, and `git commit --no-edit` to finish the in-progress merge. When fingerprints differ or any other path is unmerged, `git merge --abort` and return a loud failure — honoring the Do NOT to never silently merge differing `rules[]` arrays.

The plan correctly targets `mergeLaneToOrch` in `src/batch/engine-lanes.mjs` (the single lane→orch merge choke point used by `mergeWaveLanesToOrch` and `resume.mjs`) and defers `tests/batch/rules-manifest-merge.test.mjs` to Step 2 per PROMPT step boundaries.

### Suggestions (non-blocking)

1. **`mergeLaneToOrch` finally block** — On merge failure the function is left on `orchBranch` with `MERGE_HEAD` set; the existing `finally` checkout will fail unless the catch path either (a) completes auto-resolve + `commit --no-edit` before `finally`, or (b) runs `git merge --abort` before returning on failure. Document this ordering in implementation.
2. **Read stage blobs, not conflict markers** — Parse ours/theirs with `git show :2:${RULES_MANIFEST_REL_PATH}` and `git show :3:…` (or equivalent index-stage reads) instead of scraping `<<<<<<<` markers from the working tree.
3. **Reuse fingerprint, avoid batch→doctor import** — `fingerprintRulesManifest` already exists in `src/doctor/rules-manifest.mjs` (SP-093). Relocate or re-export it from `src/config/cursor-rules/discover.mjs` per file scope so `engine-lanes.mjs` does not depend on the doctor module; have doctor import the shared helper.
4. **Resolved write path** — Use `writeRulesManifestAtomic(projectRoot, resolvedManifest)` then `git add` the manifest path; keeps JSON formatting consistent with discovery.
5. **Failure taxonomy** — Return a distinct `failureClass` (e.g. `RulesManifestConflict` vs `MergeConflict`) when fingerprint differs or multiple paths conflict, so batch journal / operator recovery messages are actionable.
6. **Step 2 test matrix** — Cover: (a) generatedAt-only drift auto-resolves and advances `orch` HEAD; (b) differing `rules[]` aborts with loud error; (c) manifest + second file conflict aborts without auto-resolve; (d) unrelated clean merge unchanged.
