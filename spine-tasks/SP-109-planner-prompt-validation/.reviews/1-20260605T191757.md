## Plan Review: Shared validation gate (Step 1)

### Verdict: APPROVE

### Summary

Step 1 correctly closes the SP-075 / SP-107 Finding #1 regression at the planner boundary with a small shared helper module and a fail-loud gate in `buildPlan()`. The plan adds `src/tasks/packet/validate-prompt.mjs` with three composable exports — `collectPromptValidationFailure`, `formatPromptValidationFailures`, and `assertValidTaskPacket` — re-exported from `src/tasks/packet/index.mjs` for Step 2 preflight/rules reuse. `buildPlan()` collects validation failures across all selected tasks (skipping invalid packets before graph construction), then throws one aggregate `Error` listing `taskId`, optional `promptPath`, and bullet-formatted `validation.errors`. That matches the audit fix ("throw aggregate Error listing taskId + errors") and is strictly better than calling `assertValidTaskPacket` per task inside the loop, which would fail fast on the first invalid packet in multi-task scopes.

`bin/spine-plan.mjs` needs no change: `runSpinePlan()` already propagates `buildPlan` throws and `main()` prints `Error: …` and `process.exit(1)`. Targeted tests in `tests/planner/prompt-validation.test.mjs` cover invalid heading, missing testing step, missing File Scope, `runSpinePlan` rejection, and a valid-packet happy path (5/5 pass on current worktree). Collateral fixture updates in `lanes-parallel`, `pending-scope`, and `env-overrides` tests — switching ad-hoc/minimal PROMPT stubs to `minimalValidPromptMarkdown` — are necessary fallout from the new gate and belong in Step 1.
