## Code Review: Failure surfacing (Step 2)

### Verdict: APPROVE

### Summary

Step 2 delivers the detached failure-surfacing contract from the PROMPT. `readLastTaskFailedEvent` in `journal.mjs` scans the batch journal backward for the most recent `task.failed` event. `collectDetachedFailureDiagnostics` gathers a human-readable summary, a 20-line worker log tail (preferring `worker-output-<taskId>.log` when `taskId` is known, otherwise the newest lane log), and a 20-line `detached-engine.log` tail. Both `startBatchDetached` and `resumeBatchDetached` attach diagnostics on wait failures, and `formatDetachedEngineOutput` renders the excerpts in human mode. Timeout copy now reads "Engine may still be running or orphaned — run `spine status --diagnose`" with a matching `suggestedCommand`, aligning with SP-082 orphan-detection messaging.

The diff is scoped to Step 2 file scope (`detached-start.mjs`, `journal.mjs`) and does not pull in runbook or test changes deferred to Steps 3–4.

### What works well

1. **`journal.mjs:206-211`** — `readLastTaskFailedEvent` reuses `readJournalEvents` and reverse-scans; consistent with existing journal helpers and easy to unit-test in Step 3.
2. **`collectDetachedFailureDiagnostics` export** — Exposing the collector (not just the attach helper) gives Step 3 tests a stable seam for asserting journal/log tail assembly without driving full detached start/resume flows.
3. **`formatDetachedEngineOutput` failure branch** — Appends `Last task.failed`, indented worker/engine log tails with relative paths, and `→ spine status --diagnose` after the primary error line; JSON mode inherits the enriched payload via `JSON.stringify(result)`.
4. **Timeout vs engine-failure distinction** — Orphan/diagnose copy applies only to `timeout_waiting_for_batch` / `timeout_waiting_for_resume`; `batch_engine_failed` keeps phase-specific messaging while still attaching diagnostics and `suggestedCommand`.
5. **Worker log discovery** — `findWorkerOutputLogPath` matches the on-disk naming convention (`worker-output-<taskId>.log` under `lanes/lane-*`) used elsewhere in the batch stack.

### Non-blocking suggestions (Step 3+)

- **JSON payload completeness** — `attachDetachedFailureDiagnostics` computes `taskFailedEvent` but only surfaces `taskFailedSummary` on the payload. Consider including `taskFailedEvent` (or a trimmed payload subset) for `--json` consumers if operators need the full journal record.
- **Log tail I/O** — `readLogTailLines` reads the entire file before slicing. Acceptable for engine/worker logs today; if tails grow large, consider a bounded read from the end.
- **Style** — Merge the duplicate `if (batchId)` blocks in `collectDetachedFailureDiagnostics` and fix the extra indent on `diagnostics.engineLogTail` assignment (lines 125–128) for readability.
- **Tests deferred** — Step 2 checklist does not require tests; Step 3 should cover `collectDetachedFailureDiagnostics`, timeout copy, and `formatDetachedEngineOutput` failure rendering.
