## Findings

### Minor (non-blocking)

1. **Notify URL ignores `dashboard.port` from config** — `spineDashboardHandler` parses `--port` from args or hardcodes **8109** for the notification URL, while `runSpineDashboardDetached` forwards args to `spine dashboard`, which resolves the port via `resolveDashboardPort()` in `bin/spine-dashboard.mjs`. When an operator sets a non-default `dashboard.port` and omits `--port`, the server listens on the configured port but the notify text points at 8109. Fix: import/reuse `resolveDashboardPort(process.cwd(), cliPort)` for the displayed URL (same helper the CLI uses).

2. **No spawn error feedback** — `runSpineDashboardDetached` uses `stdio: "ignore"` and does not handle `child.on("error")` or check whether the port is already in use. A second `/spine-dashboard` invocation fails silently. Acceptable for v1; optional follow-up is a sync preflight or error listener before `unref()`.

3. **No handler smoke test** — Registration is covered via `SPINE_SLASH_COMMAND_NAMES` in `slash-commands.test.mjs`; there is no test asserting notify text or port resolution after the config-aware fix above.

4. **PRD §15.1 table** — `/spine-dashboard` is documented in README but not yet in `docs/PRD.md` §15.1 (out of Step 2 Must Update list; optional follow-up).
