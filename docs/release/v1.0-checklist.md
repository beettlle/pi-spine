# pi-spine v1.0 release checklist

Human approval is required before any publish step. This document prepares the release; it does not execute it.

## Pre-release

- [ ] All tasks through TP-030 complete; full test suite green (`SPINE_WORKER_STUB=1 npm test`)
- [ ] `npm run typecheck` passes
- [ ] Decide version bump: `0.0.1` → `0.1.0` or `1.0.0` (operator decision)
- [ ] Update `package.json` version
- [ ] Review `CHANGELOG` or release notes (if maintained)
- [ ] Confirm `files` whitelist in `package.json` matches shipped directories

## Dry-run pack

```bash
npm pack
tar -tzf pi-spine-*.tgz | head -50
```

Verify tarball contains:

- `bin/`
- `src/`
- `templates/`
- `extensions/`
- `skills/`
- `LICENSE`
- `package.json`
- `README.md`

Verify tarball does **not** contain test fixtures, `.spine/`, `.pi/`, or dev-only artifacts.

Remove the pack artifact after inspection:

```bash
rm pi-spine-*.tgz
```

## Publish (requires explicit operator approval)

```bash
npm login
npm publish --access public
```

**Do not run `npm publish` without explicit human approval.**

## Post-publish smoke

In a clean test project or temp directory:

```bash
pi install npm:pi-spine
spine version
spine doctor
spine init --dry-run
spine migrate-from-taskplane --dry-run --source .pi/taskplane-config.json
```

Confirm `/spine` slash commands are visible in pi after install.

## pi.dev listing

Prepare package page fields:

| Field | Source |
|-------|--------|
| Name | `pi-spine` |
| Description | `package.json` description |
| Keywords | `package.json` keywords |
| minPiVersion | `package.json` → `pi.minPiVersion` |
| Repository | `https://github.com/beettlle/pi-spine` |

## Rollback

If a bad version is published:

1. Deprecate on npm: `npm deprecate pi-spine@<version> "reason"`
2. Publish fixed patch version after fix is merged
3. Document incident in `docs/incidents/` if user-facing
