```bash

```

## Post-publish smoke

In a clean test project or temp directory:

```bash
pi install npm:pi-spine
spine version
spine doctor
spine init --dry-run
spine migrate-from-taskplane --dry-run --source .pi/taskplane-config.json
```

Confirm `/spine` slash commands are visible in pi after install.

## Version bump decision

**Decision (SP-242, 2026-06-14):** publish as **`1.0.0`**, not `0.1.0`.

| Option | Rationale |
|--------|-----------|
| **`1.0.0` (chosen)** | Phase 23–25 ship-readiness exit criteria verified (SP-225); consumer pilot filed; 838 tests + 85.92% coverage; real-pi CI hardened; first public npm release; PRD FR-SHIP-14 and this checklist target v1.0 |
| `0.1.0` (rejected) | Implies initial/unstable API; feature set matches v1.0 scope per PRD-v2.2 handoff |

**Apply:** bump `package.json` `version` to `1.0.0` in SP-226 immediately before `npm publish --access public`. Re-run `npm pack --dry-run` after bump to confirm `pi-spine-1.0.0.tgz`.

## Rollback

If a bad version is published:

1. Deprecate on npm: `npm deprecate pi-spine@<version> "reason"`
2. Publish fixed patch version after fix is merged
3. Document incident in `docs/incidents/` if user-facing
