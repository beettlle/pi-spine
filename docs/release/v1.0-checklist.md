## Publish (CI-first)

**Default path:** merge version bump to `main` → green CI → [`.github/workflows/publish.yml`](../../.github/workflows/publish.yml).

| Step | Action |
|------|--------|
| 1 | Bump `package.json` `version` on `main` |
| 2 | Confirm CI green (`ci.yml`: typecheck, tests, coverage, CLI smoke) |
| 3 | `publish.yml` runs after successful CI (or trigger **Publish to npm** via `workflow_dispatch`) |
| 4 | Workflow skips if `pi-spine@<version>` already exists on npm |
| 5 | Post-publish smoke (below) |

Secret: `NPMSECRET` (npm automation token). Publish uses `--ignore-scripts` (CI already ran `prepublishOnly` checks).

**Emergency manual publish** (CI broken, explicit operator approval only):

```bash
npm login
npm publish --access public
```

Do not use manual publish for routine releases.

**Decision (SP-242, 2026-06-14):** publish as **`1.0.0`**, not `0.1.0`.

| Option | Rationale |

If a bad version is published:

1. Deprecate on npm: `npm deprecate pi-spine@<version> "reason"`
2. Publish fixed patch version after fix is merged (CI-first flow on `main`)
3. Document incident in `docs/incidents/` if user-facing
