## Proof sequence (summary)

Run after manifest tasks (SP-543–549) land on `main`:

```bash
./scripts/release-proof-gate.sh

# Record baseline open-issue count (M-AUTO-02) — see Post-mortem section
gh issue list --state open --json number | jq 'length'

spine run sequence SP-543,SP-544,SP-545,SP-546,SP-547,SP-548,SP-549,SP-550,SP-551 --auto-approve-gate --detached
```

Human actions during waves: **`spine gate approve`** only. No `spine batch pause`, `retry`, or `resume --force`. Publish approval is separate (Phase 6).

Record **batch ID** from sequence start output or `spine status --diagnose`.

## Post-mortem (FR-STA-32)

After all manifest-scoped tasks are `.DONE` and before `npm version minor`, commit proof evidence to the repo. An operator should be able to complete this section using only this runbook — no PRD required.

### When to run

1. Proof sequence complete (all waves integrated).
2. `npm run release:check` green (M-AUTO-03).
3. `spine plan <manifest-scope>` shows **0** pending (M-AUTO-04).
4. **Before** tag push — post-mortem is a publish gate input per [`automation-signoff-checklist.md`](automation-signoff-checklist.md).

### Journal export

Export the full orchestration timeline for audit and signoff verification (M-AUTO-01).

```bash
# Markdown timeline (default for human post-mortems)
spine journal export --batch <batchId> --format markdown --output docs/release/proof-v2.0.0-journal.md

# JSONL (machine replay / Babysitter)
spine journal export --batch <batchId> --format jsonl --output docs/release/proof-v2.0.0-journal.jsonl
```

Both formats read `.spine/runtime/<batchId>/journal/events.jsonl` and exit non-zero when the journal is missing.

### Batch post-mortem path

pi-spine writes an honest batch summary at batch completion:

```text
.spine/runtime/<batchId>/post-mortem.md
```

Copy or reference this path in the committed post-mortem artifact. It includes task outcomes, merge/gate/integrate status, and recovery suggestions (NFR-OBS-03, TP-022).

```bash
# Inspect engine-generated post-mortem
cat .spine/runtime/<batchId>/post-mortem.md

# Optional: commit a snapshot alongside journal export
cp .spine/runtime/<batchId>/post-mortem.md docs/release/proof-v2.0.0-batch-post-mortem.md
```

### Commit checklist

```bash
git add docs/release/proof-v2.0.0-post-mortem.md \
        docs/release/proof-v2.0.0-journal.md
# Add jsonl and/or batch-post-mortem copy if used

git commit -m "docs: v2.0.0 proof post-mortem (batch <batchId>)"
```

Then complete the **Post-mortem committed** section in [`automation-signoff-checklist.md`](automation-signoff-checklist.md) before publish approval (Phase 6).
